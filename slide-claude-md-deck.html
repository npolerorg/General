CLAUDE.md — El Mandato de IA de Toyosa

Antes de cada conversación, Claude lee este archivo. Define quiénes somos, cómo operamos y qué reglas debe seguir — se convierte en parte de los lineamientos oficiales de la organización.
1
Por qué hacerlo
Uso eficiente de tokens (menor costo), mayor velocidad de respuesta, calidad y consistencia en cada output, base para generar agentes especializados, y trazabilidad para auditoría.
2
Contestar cuestionario
Claude entrevista al equipo: industria, unidades de negocio, tono, stack tecnológico, canales, idiomas, políticas de datos y secretos.
3
Validar información
Revisar el borrador con stakeholders clave. Ajustar reglas críticas — verificación, manejo de clientes, finanzas — antes de aprobar.
4
Repositorio centralizado
Commit en Git. Una sola fuente de verdad, versionada y auditada, accesible para todo el equipo y reproducible en cada estación.
5
Despliegue global
Copia a ~/.claude/CLAUDE.md en cada equipo. Toda sesión nueva — de cualquier colaborador — aplica las reglas automáticamente.
!
Esto es lo que Claude lee ANTES de comenzar cualquier tarea. Se convierte en el mandato operativo de Toyosa frente a la IA — sus principios, su voz y sus límites, aplicados de forma consistente en cada interacción de cada colaborador.

Dos Niveles de Configuración: Global + Local

El Global define la identidad y reglas que aplican siempre. El Local define el contexto específico de cada proyecto, cliente o BU. Claude lee ambos en cada sesión y los aplica como un solo mandato.
NIVEL 1GLOBAL
~/.claude/CLAUDE.md
Reglas transversales que aplican en cada sesión, en cada proyecto, sin excepción.
  • Identidad y objetivos de la organización (Toyosa: holding, BUs, geografías)
  • Voz y tono (idioma, formalidad, estilo de comunicación)
  • Verificación crítica — nunca inventar cifras ni inferencias en temas financieros o de cliente
  • Comportamiento por tarea — qué requiere plan previo, qué se ejecuta directo
  • Estrategia de razonamiento — cuándo decomponer, cuándo presentar trade-offs
  • Conservación de tokens y contexto — uso de subagentes y lazy-loading
  • Manejo de secretos — .env por proyecto, vault corporativo para credenciales
  • Stack tecnológico preferido (Tableau, Alchemy, MCPs, Skills)
  • Reglas de comunicación externa — drafts, threads, canales (email/WhatsApp)
NIVEL 2LOCAL
proyecto/CLAUDE.md
Contexto específico de cada proyecto, BU o engagement. Uno por carpeta de trabajo.
  • Overview y non-goals — qué cubre el proyecto y qué explícitamente NO
  • Players y contactos — nombres, roles, emails, jerarquía
  • Tech stack del proyecto — sistemas propios + integraciones
  • Locked numbers — cifras verificadas trazables a fuente (EERR, Directorio)
  • Architecture & patterns — decisiones técnicas, restricciones, arquitectura
  • Hard rules — prohibiciones específicas (ej: "Edwin Saavedra nunca como Jr.")
  • Comandos — scripts, deploys, herramientas del entorno
  • Canary — frase obligatoria que prueba que el archivo se cargó
  • References — docs, decks, threads, grabaciones load-on-demand
▶
Cada sesión nueva: Claude lee primero ~/.claude/CLAUDE.md (Global) → luego el CLAUDE.md del proyecto activo (Local) → combina ambos como su mandato operativo. La frase canary en la primera respuesta verifica que ambos archivos cargaron correctamente.

¿Qué es MCP? · El protocolo que conecta Claude con sus sistemas

Model Context Protocol — estándar abierto creado por Anthropic. Cada MCP server convierte un sistema empresarial (Tableau, ERP, WhatsApp, Gmail, Drive) en herramientas que Claude puede invocar directamente. Sin integraciones a la medida, sin reentrenamiento, sin mover datos fuera de su entorno.
BI
Tableau MCP
Lee dashboards, ejecuta queries, exporta visualizaciones, accede al modelo de datos via Metadata GraphQL.
Uso Toyosa: síntesis multi-dashboard, what-if engine, auto-narración para directorio.
ERP
Alchemy ERP
MCP a la medida con acceso read-only controlado a financials, stock, CxC, cierres mensuales.
Uso Toyosa: reconciliación intercompany, costos reales por unidad, visibilidad de tránsito.
DOCS
Google Drive MCP
Lee y escribe documentos, hojas, presentaciones. Acceso a EERR auditados, propuestas, decks.
Uso Toyosa: generación automática de PPT directorio, archivo de entregables, búsqueda en histórico.
CHAT
WhatsApp MCP
Envía alertas y recibe queries en lenguaje natural desde grupos del directorio y operación.
Uso Toyosa: cash flow sentinel, alertas de inventario aging, Q&A ejecutivo en tiempo real.
MAIL
Gmail MCP
Lee threads, redacta drafts, archiva conversaciones, etiqueta automáticamente por proyecto/cliente.
Uso Toyosa: AI Board Member email diario, drafts ejecutivos, seguimiento de threads críticos.
CRON
Scheduled Tasks
Ejecuta workflows recurrentes sin intervención humana: diario, semanal, mensual, o disparado por eventos.
Uso Toyosa: reporte directorio mensual, audit semanal, cash flow projection diaria.
▶
Diferenciador clave: Claude no es "otro dashboard" ni un chatbot aislado — es la capa de inteligencia que orquesta los sistemas que Toyosa ya tiene. MCP permite agregar capacidades sin reemplazar Tableau, sin tocar Alchemy, sin mover data. Cada MCP nuevo amplía lo que Claude puede hacer; ninguno pone en riesgo lo existente.

Herramienta de discovery: claude-code-setup

Plugin oficial de Anthropic que analiza un codebase y recomienda automatizaciones. Lo usaremos en la fase de implementación para auditar cada repo de Toyosa (Toyosa Holding, Intermex, Crown) y proponer la configuración óptima por BU.
Qué hace
Scanner read-only
  • Escanea estructura del proyecto y detecta patrones
  • Recomienda top 1-2 en cada categoría:
  • MCP Servers — integraciones externas
  • Skills — capacidades empaquetadas
  • Hooks — acciones automáticas (lint, format)
  • Subagents — revisores especializados
  • Slash Commands — workflows rápidos
  • Devuelve lista priorizada, lista para revisar
Qué NO hace
No es magia ni reemplazo
  • No modifica archivos — solo recomienda
  • No instala MCPs ni configura hooks por sí solo
  • No reemplaza el CLAUDE.md — es input, no output
  • No conoce el negocio — no sabe quién es Edwin, qué es Alchemy, ni las reglas duras
  • No es un one-click setup — la decisión final y la implementación las hace nuestro equipo
▶
Cuándo lo corremos: al pasar de Discovery a Implementación, una corrida por repo/BU. La salida alimenta el CLAUDE.md de cada proyecto — combinamos sus recomendaciones técnicas con el contexto de negocio que ya tenemos validado con Edwin y Juan Carlos.
